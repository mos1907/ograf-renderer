EBU OGraf v1

Broadcast Graphics Pipeline

From After Effects to live broadcast output — how OGraf templates are created, packaged, and rendered.

🎨
Phase 1
Design in After Effects
→ Create your graphic — lower third, scoreboard, ticker, logo reveal, or any broadcast overlay
→ Mark dynamic fields — use text layers and expression controls for data that will change at runtime (names, scores, headlines)
→ Define animation segments — separate IN (entrance), LOOP (hold), and OUT (exit) sections using markers or pre-comps
.aep project shape layers text layers
↓
📦
Phase 2
Export with Bodymovin

Install the Bodymovin plugin for After Effects and export your composition as a Lottie JSON file. This captures all keyframes, easing curves, shape data, and masks as resolution-independent vectors.

animation.json fonts/ images/ (if any)
↓
⚙️
Phase 3
Package as OGraf Template
→ Import into Ferryman — load your Lottie JSON at streamshapers.com
→ Define editable fields — map text layers to a data schema (string, integer, color)
→ Map animation segments — assign IN/OUT markers to playAction and stopAction
→ Export OGraf package — a self-contained folder ready to drop into the renderer
manifest.ograf.json graphic.mjs lib/animation.json lib/fonts/
Alternative: Write the Web Component by hand using vanilla HTML, CSS, and JavaScript — define a custom element with play(), stop(), update(), and next() methods. No After Effects needed.
↓
🚀
Phase 4
Drop into Templates Folder

Copy the OGraf package folder into the templates/ directory. The renderer watches this folder and automatically detects new templates — no restart needed.

→ Template appears in the control panel dropdown
→ Data fields are generated from the manifest schema
→ Transport buttons adapt to the template's actions and step count
templates/your-graphic/
↓
📡

Ready for broadcast.
Play, stop, update data, and trigger custom actions
from the control panel at localhost:4000
